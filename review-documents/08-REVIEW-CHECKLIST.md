# Reviewer Checklist

## Product review

- [ ] The two-sided CA and business-owner model is understandable.
- [ ] The application solves a clear document-chasing and data-quality problem.
- [ ] The first target customer and business vertical are defined.
- [ ] Prototype features and production features are clearly separated.
- [ ] The owner application is simple enough for non-accounting users.
- [ ] The CA application provides sufficient review and approval control.

## Functional review

- [ ] Practice dashboard and client list load correctly.
- [ ] Client 360 presents compliance and operational context.
- [ ] Client document submission updates the practice workflow.
- [ ] Voice invoice parses the sample and calculates GST correctly.
- [ ] Duplicate invoice creation is prevented.
- [ ] E-Way Bill preparation validates GSTIN, HSN, vehicle and distance.
- [ ] Purchase capture reaches the CA review queue.
- [ ] Reset demo restores the initial state.

## Technical review

- [ ] Production architecture is acceptable.
- [ ] Data model supports multiple firms and clients.
- [ ] Authorization is enforced on the backend.
- [ ] Secrets and provider credentials stay out of browser code.
- [ ] Audit records are append-only.
- [ ] Error monitoring, backups and recovery are planned.
- [ ] Automated tests are required before production.

## Compliance review

- [ ] GST and E-Way Bill integrations use an authorized provider.
- [ ] Human approval is mandatory for statutory submission.
- [ ] Client data processing and privacy documents are prepared.
- [ ] Retention and deletion periods are defined.
- [ ] AI data access and output review are controlled.
- [ ] The recurring referral-share model has legal and ICAI review.

## Commercial review

- [ ] Pricing for custom development, support and integrations is defined.
- [ ] Referral calculation, tax and payout terms are documented.
- [ ] Ownership of custom code and client data is defined.
- [ ] Service levels, support hours and change requests are defined.
- [ ] Third-party API and messaging costs are allocated.

## Review decision

- [ ] Approved for continued prototype development.
- [ ] Approved for a controlled pilot.
- [ ] Changes required before pilot.
- [ ] Security/compliance review required.
